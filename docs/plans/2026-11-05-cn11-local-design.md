# CN11 本地测试版：实时接管与独立恢复

用户已明确批准按已讨论方案制作本地测试版，先完成实时接管及异常退出恢复，稳定后再发布。

## 接入边界

- 保留已完成的连续消息合并、版本关闭保护和前台免打扰。新增显式实时模式，初始关闭；接管需要辅助功能访问和系统自身生成桌面横幅。
- 实时入口采用 NotificationCenter AX 树；识别来源和完整内容后才接管。无法识别、权限不足或恢复看护不可用时保留/恢复原生提醒，避免隐藏用户未读消息。
- 实时模式不从数据库重新弹出被系统共享/专注策略静音的内容。数据库继续只读，用于去重和一致性核对；传统模式保留数据库补偿。故障回退原生，不同时双弹。
- 不自动修改 macOS 原生通知开关或共享屏幕隐私策略。测试时的任何临时全局隐私调整仍需当次确认。

## 恢复优先

- 同一已签名 executable 以专用参数运行当前用户的独立看护，早于常规设置/剪贴板初始化进入看护分支。不安装 root 服务或 LaunchAgent，不扩大权限。
- 主程序主线程发送心跳，看护持有独立 AX 引用、原坐标和仅窗口元数据的本地恢复日志。看护执行移动；未完成 ready/park 确认不隐藏。
- EOF、父进程死亡、心跳超时、正常关闭模式均触发复位。看护异常时主程序本地复位并停止接管。冷启动在模式关闭时也处理残留日志。
- 校验 NotificationCenter 进程启动时间、窗口 ID、角色、尺寸和受管位置，不覆盖用户主动移动/系统新建窗口。权限撤回或整个会话都被强杀时存在系统边界，保留残留记录并明确显示，不能声称永远无条件恢复。
- 恢复日志只存窗口位置、标识和会话状态，不存来源消息、正文或验证码；不建数据库、不改现有业务数据库。

## 实现与职责

主 agent 负责实时 AX 服务、现有通知管理器接入、设置界面、AppDelegate 生命周期、CN11 版本、签名安装和运行验证。

恢复子 agent 仅新增 NotificationWindowRecovery.swift（必要时 NotificationRestoreAgent.swift）及专用验证脚本。模型子 agent 仅新增 NotificationRealtimeModel.swift 和验证脚本。主 agent 审查与集成，不并发修改同一文件。

## 验证与发行

扩展现有回归并增加必要的协议/模型验证，完整构建；先验证看护握手、父进程崩溃、看护退出、失去心跳及残留恢复，再验证真实连发、前台抑制、跨来源去重、退出复位和多屏变化。本机生成 CN11 有效签名测试包；本轮不推送 GitHub/OSS 或更新清单。未知或未通过的场景明确记录，不能只凭原型结果宣称稳定。
