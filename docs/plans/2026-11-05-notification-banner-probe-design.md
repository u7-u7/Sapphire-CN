# 实时横幅路线可行性验证

用户在已安装连续刷新修复后明确选择继续验证实时监听路线。

现有证据：三条 200ms 间隔的真实测试通知合并显示最新一条；通知数据库 WAL 元数据在一次控制测试中于请求后 5.414 秒变化，展示状态约 40ms 后更新。其他样本的等待超过 5 秒，因此不把该延迟归因于 UI 排队，也不宣称已解决通用实时通知入口。

第一阶段只在 Debug、本机显式开关下运行限时探针：复用现有 AXObserverHandle 和 AX 工具，监听 NotificationCenter UI，后台有界扫描，识别固定测试标记，不记录任何真实通知正文。探针默认关闭且限时自动停止。

仅以 Sapphire 自身测试通知验证：先观察原生桌面横幅关闭时的可见性，再临时开启 Sapphire 的原生桌面横幅，观察能否在落盘前检测，以及元素支持哪些隐藏/移除动作。其他应用保持原设置；隐藏动作须验证不会清除通知中心历史。无法保证隐藏或权限不足时停止接管，不假装实时能力已实现。

验证后恢复测试开关和原生通知设置。确认可行之前不将实验路线默认启用，也不发布新版本。
