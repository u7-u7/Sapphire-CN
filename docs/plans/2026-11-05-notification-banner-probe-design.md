# 实时横幅路线可行性验证

用户在已安装连续刷新修复后明确选择继续验证实时监听路线。

现有证据：三条 200ms 间隔的真实测试通知合并显示最新一条；通知数据库 WAL 元数据在一次控制测试中于请求后 5.414 秒变化，展示状态约 40ms 后更新。其他样本的等待超过 5 秒，因此不把该延迟归因于 UI 排队，也不宣称已解决通用实时通知入口。

第一阶段只在 Debug、本机显式开关下运行限时探针：复用现有 AXObserverHandle 和 AX 工具，监听 NotificationCenter UI，后台有界扫描，识别固定测试标记，不记录任何真实通知正文。探针默认关闭且限时自动停止。

仅以 Sapphire 自身测试通知验证：先观察原生桌面横幅关闭时的可见性，再临时开启 Sapphire 的原生桌面横幅，观察能否在落盘前检测，以及元素支持哪些隐藏/移除动作。其他应用保持原设置；隐藏动作须验证不会清除通知中心历史。无法保证隐藏或权限不足时停止接管，不假装实时能力已实现。

验证后恢复测试开关和原生通知设置。确认可行之前不将实验路线默认启用，也不发布新版本。

## 第一轮结果（未确认可用）

Sapphire 原有辅助功能访问已开启，没有扩大系统权限。探针正常创建四类 AX 事件订阅，并能枚举通知中心窗口；默认桌面关闭和短暂开启 Sapphire 自身桌面提醒两种条件下，都没有匹配到固定测试标记。系统界面检查仅选到通知中心的日历组件，尚不能据此判定原生横幅未出现或该路线不可能。

没有执行任何横幅隐藏、取消或通知记录删除动作。测试后已逐项确认 Sapphire 桌面关闭、通知中心和总开关仍开启，恢复原测试开关并停止日志观察进程；限时探针已自动停止。全局屏幕共享通知策略及其他应用设置保持原状。

后续需要确认用户实际是否看到了原生测试横幅，再区分系统屏蔽（全局共享屏幕时关闭通知也是待核实因素）、窗口所属进程及 AX 树解析问题。目前不把实验标记为实时捕获成功。

## 隔离持续横幅对照

用户反馈未留意第一轮横幅。改用同一应用签名身份的临时隔离测试程序，不启动剪贴板等无关模块；只发送一个有唯一标记的自身通知，同时查询自身公开通知 API 和枚举通知中心 AX 树。只临时将 Sapphire 自身的桌面提醒设为持续，未改变其他应用或全局共享策略。

- 记录的辅助功能信任为 true，自身通知权限、桌面提醒、持续样式和通知中心均已开启。
- 自身公开通知 API 在发送约 0.206 秒后返回已送达；AX 没有匹配到测试标记，未执行任何窗口移动/隐藏。
- 系统日志对此唯一测试请求明确返回 `resolutionReason: display shared`、`interruptionSuppression: silence`；通知中心记录 `muted: true`、`canDisplayWhileCenterIsClosed: false`。这说明测试横幅被共享屏幕时静音，不能据此判定 AX 路线本身不可行。
- 测试程序仅清理自身创建的唯一测试通知并自动退出；已恢复 Sapphire 原有桌面关闭、临时样式、通知中心开启，正常连续刷新修复版已恢复运行。最初临时 Debug 探针代码已撤除，实验程序仅保留在本机临时目录。

继续对照需要临时放宽“当镜像或共享屏幕时”的全局通知隐私设置；已按电脑操作工具规则单独询问用户，未在获准前修改。该设置可能使其他允许桌面提醒的应用在共享画面中显示内容。

## 共享策略获准后的对照与可逆移动

经用户当次明确确认，短暂允许共享屏幕时显示通知，仅对 Sapphire 自身发送受控通知。第一轮在 0.605 秒读取到唯一标记；随后恢复全局关闭策略、Sapphire 桌面关闭及临时样式，并恢复正常修复版。

第二轮在另行当次确认后进行可逆移动验证：

- 通知中心记录约 0.208 秒可由本应用公开 API 读取，AX 在约 0.369 秒捕获横幅。
- 实际承载横幅的窗口是 `AXSystemDialog`，大小为 1470×956，是整层透明通知浮窗，不能将它当作单个小横幅。
- 对仅包含本轮唯一测试标记的新通知浮窗，位置设置成功，立即、200ms 与 1 秒后的坐标均位于屏幕外。
- 移出期间本轮通知仍在通知中心；2 秒后成功恢复原坐标。未对其他通知执行关闭或删除；测试程序仅清理自己创建的通知。
- 结束后立即恢复共享屏幕通知关闭、Sapphire 桌面关闭和临时样式，正常修复版重新安装。

上述结果只证明本机受控单条通知的实时读取及可逆移动，不代表正式接管功能已实现。快速第二条消息是否导致窗口复位、移出后是否还能读取更新、通知中心展开及异常退出恢复仍需验证。已准备 300ms 连发的测试程序，尚未在新的当次共享策略确认前运行。

## 临时横幅下的快速第二条通知

用户再次明确允许该轮临时共享策略调整后执行。Sapphire 自身使用“临时”横幅，首条捕获并移出屏幕后，300ms 后发送独立的第二条通知。

- 首条 AX 捕获延迟约 0.586 秒；第二条在发送后约 0.721 秒被 AX 读到。
- 第二条仍属于同一个 AX 窗口，捕获时窗口位于屏幕外；一秒坐标复核仍在屏幕外，系统没有因这条更新把浮层移回来。
- 两条通知均保留在通知中心，2 秒后原坐标恢复成功。临时测试只清理本轮生成的两个通知标识，程序自动退出。
- 全局“当镜像或共享屏幕时”恢复“关闭通知”，Sapphire 桌面关闭、临时样式和通知中心开启均已核对。签名正常的连续刷新修复版已恢复运行，未再扩大任何授权。

结论：本机受控单条及快速第二条的 AX 读取、移出后继续更新、短时隐藏和保留记录均有实测依据。此结果不是日常版本已接入实时模式的声明；通用来源识别、与数据库的跨来源去重、通知中心主动展开、多屏及异常退出恢复仍是正式接入前的工作。共享屏幕原有静音策略必须继续尊重，不能把本轮临时批准视为永久修改许可。
