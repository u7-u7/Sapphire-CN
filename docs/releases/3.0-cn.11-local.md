# CN11 本地测试记录

版本为 `3.0 (11)` / `3.0-cn.11-preview`，本地标记为 `CN11 realtime local test`。仅本机安装，未创建 GitHub Release、上传 OSS 或修改公开更新清单。

## 行为

- 保留连续消息按应用刷新、6 秒展示、跨应用等待上限、回复编辑保护和前台来源免打扰。
- 新增默认关闭的实时接管模式。来源应用需生成桌面横幅；未知来源、布局不完整或看护未就绪时保留原生。
- 独立同用户看护先记录原坐标再隐藏。主程序死亡或主线程停止心跳时复位；看护死亡时主程序尝试复位。两者同时死亡时依靠下一次启动恢复日志。
- 恢复日志仅含窗口和进程元数据，权限 0600，不保存通知正文，不创建业务数据库。
- 实时模式不通过数据库补弹系统已静音的通知；原数据库模式继续保留。不开启或修改系统全局通知隐私选项。

## 已验证

- Debug arm64 完整构建通过。
- 连续消息、旧回调、回复保护、前台策略及展示计时回归通过。
- 保守解析、未知兄弟保留、来源边界、去重及模型序列化回归通过。
- 恢复租约、进程启动标识、坐标约束、屏幕移除、IPC 分帧、日志权限和损坏输入回归通过。
- 真实 socket 背压及时失败、EAGAIN/EOF 区分、断连无 SIGPIPE 回归通过。
- 主程序和独立恢复 executable 使用有效同团队、同 identifier 签名，深度严格验签通过。
- 从正常应用启动路径运行受控 Debug 验收入口：已有辅助功能授权有效；看护握手成功；正常结束后两进程退出，无残留恢复日志。终端直接执行的权限归属不同，不能据此判定应用授权丢失。
- 正常设置界面开启后显示“实时接管已就绪”；强杀看护后主程序存活并显示停止接管，可重新连接。暂停主程序 3.5 秒，看护因心跳超时退出，恢复主程序后显示停止接管。以上两项当时没有隐藏中的窗口，只验证进程降级，不能替代坐标复位验收。结束后已关闭测试开关，保留传统模式。

## 仍需验收

当前共享屏幕通知仍为“关闭通知”，Sapphire 桌面提醒仍关闭。临时放宽共享通知需当次授权，因此本轮尚未完成真实横幅接管、父进程强杀/冻结、看护强杀和双方退出后恢复坐标的验收。先前原型的成功结果不能替代 CN11 集成版本验收。

还需覆盖真实应用连发、通知中心展开、用户主动移动、锁屏/休眠、多屏变化、AX 权限撤回、整组强制退出及长时间运行。完成前不能标记稳定或默认开启。
