# Sapphire-CN CN8：Codex 桌面版内置 CLI 识别修复

标签：`v3.0-cn.8-preview`。Apple 芯片 arm64，项目最低 macOS 14.6。系统版本 `3.0 (8)`，签名内发行标识 `3.0-cn.8-preview`。

## 本版修复

此前只安装桌面应用、未独立安装 CLI 的用户，从 Finder 启动 Sapphire 时可能遇到“未找到 Codex CLI”；即使桌面版已有有效登录，刷新额度也无法执行。

- 增加 Codex / ChatGPT 桌面应用内置 CLI 的查找，覆盖 `/Applications` 与当前用户的 `~/Applications`。
- 兼容原有 `Contents/Resources/codex` 布局及新版 `Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex` 布局。
- 用户目录动态通过 `NSHomeDirectory()` 获取，不写死开发机器用户名。
- 保留 `~/.local/bin` 与 Homebrew 入口的优先级，并继续支持 nvm 和 PATH 查找。
- 更新后无需为本次路径问题手工创建软链；仍需有效登录。Claude 凭据独立处理，修复 Codex 路径不会自动登录 Claude。
- 保留 CN7 权限设置入口修复。额度查询不创建模型任务，不复制或修改 CLI 凭据，也不绕过服务端限流及应用刷新冷却。

## 升级方式

**CN6、CN7 用户可通过“设置 → 关于 → Sapphire 更新”获取 CN8，也可手动安装。** 本版继续使用团队 `462JAMGP66` 证书，主程序与 Helper 同团队签名。

**CN4 及更早版本、CN5 临时签名版用户需手动安装一次 CN8。** 请先退出并备份原应用，再把完整应用安装到 `/Applications/Sapphire.app`。旧团队或临时签名无法直接通过同团队校验自动安装本版。

跨团队迁移后如 Helper 连接失败，请重新配置辅助服务并检查后台运行权限。后续同团队版本沿用应用内更新，安装仍需本人确认。

## 验证与边界

- 完整 Debug arm64 构建通过，主应用 build 递增至 8。
- 108 项离线 AI 额度检查通过，包含新增的 8 项可执行文件查找回归检查；覆盖缺少终端 PATH 的桌面 CLI 发现、系统/用户应用目录、旧布局、本地 bin 入口优先级与缺失文件。
- 本机文件系统验证通过：使用精简 GUI PATH，并明确排除临时兼容软链，仍能解析到当前桌面版内置 CLI。路径检查不读取凭据或请求网络。
- 先前同一修复代码通过本机内置 CLI 的只读额度查询取得额度窗口；不公开账户标识、凭据或个人额度读数。
- 由内向外沿用 CN6 的有效证书及权限声明签名，使用安全时间戳，保留 Helper 空权限声明与 hardened runtime。
- 使用真实 Security framework 严格检查主程序、Helper、证书链和嵌套代码，核对应用标识、团队、版本、arm64 架构及中文资源。
- 校验 DMG、只读挂载后的应用、ZIP 路径和软链、解包签名以及主程序/Helper 摘要；核对 CN6/CN7 至 CN8 的签名要求一致与 build 单调递增。
- 本版仍为 Apple Development 签名、未公证开发预览。完整自动安装、其他 Mac、整机重启及各账号的实际额度服务仍需安装后验收。未登录、冷却或服务错误不会显示伪造额度。
