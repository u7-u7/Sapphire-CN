# Sapphire-CN CN11：连续通知优化与实验实时接管

标签：`v3.0-cn.11-preview`。Apple 芯片 arm64，macOS 14.6 起。系统版本 `3.0 (11)`，发行标识 `3.0-cn.11-preview`。

**实验实时模式默认关闭。真实横幅接管、隐藏中横幅的崩溃坐标恢复尚未完成验收，本版不标记为稳定。**

## 更新内容

- 同应用连续消息立即刷新当前提醒并重新计时，其他应用各保留最新一条，避免逐条等待。普通提醒展示 6 秒，有其他应用等待时限制同一应用连续占用至 12 秒；输入回复时保护当前消息。
- 修复正文更新遗漏和旧弹窗关闭回调误关新消息；保留前台来源应用免打扰。
- 保留传统通知数据库模式，改善 WAL/目录变化监听与连接恢复。系统写入通知记录可能延迟数秒，不能把轮询间隔当成端到端延迟保证。
- 新增默认关闭的“实时通知接管（本地测试）”实验入口。识别来源与完整内容、并确认恢复看护就绪后才隐藏系统横幅；未知来源、歧义布局和权限不足时保留原生通知。
- 新增独立同用户恢复进程。主程序退出、卡顿失去心跳或看护异常时停止接管并尝试复位；两进程同时被杀时需下次启动恢复，不能保证即时复位。
- 公开包不含本机测试标记，也不启用受控诊断启动入口。保留 OSS 优先更新及 GitHub 回退。

## 选择通知模式

传统模式沿用 CN10：为 Sapphire 开启完全磁盘访问权限。需要只在岛上提醒时，在 macOS 对应应用通知页关闭“桌面”，保留“允许通知”和“通知中心”；该系统设置退出 Sapphire 后仍生效。

实验实时模式需要现有辅助功能授权，以及来源应用开启 macOS“桌面”临时横幅。不要同时沿用传统模式的“关闭桌面”设置。Sapphire 不自动修改系统通知开关，遵从专注与共享屏幕静音；实时模式不通过数据库补弹被系统静音的通知。可在设置页关闭接管并恢复原生。

恢复日志只保存进程与窗口元数据，权限为 0600，不保存通知正文，不新建业务数据库。应用自绘弹窗不属于系统通知接管范围。

## 验证与限制

- 完整 Debug arm64 构建、连续消息与展示策略、保守解析与去重、恢复协议及真实 socket 背压/断连回归通过。
- 本机正常启动确认已有辅助功能授权有效、看护握手及正常退出清理通过；设置页可开启到“就绪”，并关闭回到传统模式。
- 在没有隐藏中横幅的情况下，强杀看护后主程序存活并降级；暂停主程序 3.5 秒后看护按心跳超时退出，主程序恢复后停止接管。
- **以上进程测试不能替代真实窗口坐标恢复测试。** CN11 的真实横幅解析、接管、连发、多应用、展开通知中心、隐藏中崩溃恢复，以及休眠、多屏、其他系统版本仍需验收；早期原型结果不等同于集成版通过。
- 沿用团队 `462JAMGP66` 的 Apple Development 签名和安全时间戳，仍为未公证开发预览。系统扩展等公开源码占位功能范围不变。

CN6–CN10 可通过“设置 → 关于 → Sapphire 更新”升级；CN9–CN10 优先走 OSS，CN6–CN8 旧客户端仍走 GitHub。CN4 及更早版本、CN5 临时签名版需手动安装一次完成团队迁移。升级后如出现钥匙串提示，请仅在系统窗口亲自验证。
